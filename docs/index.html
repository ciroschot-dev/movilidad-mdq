01

El problema y el objetivo

Moverse por Mar del Plata obliga a abrir varias apps (Taxi, Uber, Didi), cada una con su tarifa, para saber cuál conviene. No hay una forma rápida de comparar de un vistazo cuánto sale ir de un punto A a un punto B.

MovilidadMDQ resuelve esto: el usuario ingresa origen y destino, y la app calcula la distancia, el tiempo y el precio en Taxi, Uber y Didi, sumando el clima del destino y un historial personal de viajes.

Dominio elegido: comparador de movilidad urbana. Tiene varias entidades relacionadas (usuarios, viajes, tarifas), reglas de negocio reales, integración con APIs externas y necesidad de autenticación — complejidad suficiente para el TP.

05

Decisiones técnicas clave

DTOs como records

Objetos de transferencia inmutables y concisos, desacoplados de las entidades JPA de base de datos.

Servicios especializados

TarifaService, UberDeepLinkService, DidiDeepLinkService, GoogleMapsService y WeatherService: una única responsabilidad cada uno.

Manejo de errores central

Un GlobalExceptionHandler traduce de forma automática las excepciones de dominio a respuestas claras HTTP.

Configuración externa

Tarifas parametrizables y editables en la base de datos; credenciales y secretos en variables de entorno.

Organización del código en capas

1

lógica de negocio
3

acceso (JPA)
4

entidades de BD

Capas de soporte transversal: dto (records de request/response), enums, config, security y exception.

¿Por qué esta organización? Cada capa tiene una única responsabilidad: el controller no sabe de SQL, el service no sabe de HTTP. Eso hace el sistema más fácil de entender, testear y mantener.

11

Autenticación (JWT y Google OAuth2)

Flujo con JWT

Login
Backend JWT
Front Storage

En cada request protegida el frontend manda Authorization: Bearer <token>. Un filtro de Spring Security valida el JWT.

Flujo OAuth2 con Google

  1. El usuario hace clic en "Continuar con Google".
  2. El frontend redirige al backend (/oauth2/authorization/google).
  3. Google autentica y redirige de vuelta al backend.
  4. El backend genera un **JWT propio** firmado y redirige al frontend con el token.
12

Autorización y roles

Rol Permisos y endpoints habilitados
USER Calcular viajes, ver/editar perfil, consultar su propio historial y viaje frecuente
ADMIN Todo lo del rol USER + capacidad de actualizar la tarifa de Taxi

Públicos: endpoints de registro y login. Privados: todo el resto (JWT requerido).

Seguridad por Rol: los datos personales e historial quedan protegidos en base al ID del token, y la actualización de tarifas está restringida sólo al administrador.

15

Dificultades encontradas y resolución

Precios reales de Uber y Didi

No exponen APIs públicas de consulta y bloquean scraping.

**Resolución:** Algoritmo dinámico basado en clima, distancia e historial.

Conectar Vercel y EC2

Habilitar certificados SSL e integrar HTTPS en el backend de producción.

**Resolución:** Proxy reverso y dominio DDNS seguro.

Manejo de secretos

Mantenimiento estricto de credenciales fuera del código fuente.

**Resolución:** Variables de entorno inyectadas en AWS y Vercel.
